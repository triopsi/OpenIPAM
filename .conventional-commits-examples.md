# Conventional Commits Examples für Laravel IPAM

Dieses Dokument zeigt Beispiele für korrekte Commit Messages im Conventional Commits Format.

## Format

```
<type>[optional scope]: <description>

[optional body]

[optional footer(s)]
```

## Commit Types

### Features (Minor Version Bump)
```bash
git commit -m "feat: add mass IP creation with CIDR subnet support"
git commit -m "feat(auth): implement email-based two-factor authentication"
git commit -m "feat(ui): add Gravatar integration for user profiles"
```

### Bug Fixes (Patch Version Bump)
```bash
git commit -m "fix: resolve IP address validation for IPv6 addresses"
git commit -m "fix(auth): correct 2FA code expiry time calculation"
git commit -m "fix(ui): fix responsive layout on mobile devices"
```

### Performance Improvements (Patch Version Bump)
```bash
git commit -m "perf: optimize database queries for large IP ranges"
git commit -m "perf(cache): implement Redis caching for device lookups"
```

### Security Updates (Patch Version Bump)
```bash
git commit -m "security: update dependencies to fix CVE-2024-1234"
git commit -m "security(auth): strengthen password validation rules"
```

### Documentation (Patch Version Bump)
```bash
git commit -m "docs: update README with Docker setup instructions"
git commit -m "docs(api): add OpenAPI documentation for REST endpoints"
```

### Code Style (Patch Version Bump)
```bash
git commit -m "style: apply Laravel Pint formatting rules"
git commit -m "style(components): standardize Filament component structure"
```

### Refactoring (Patch Version Bump)
```bash
git commit -m "refactor: extract IP validation logic into service class"
git commit -m "refactor(models): simplify User-Device relationship methods"
```

### Tests (No Version Bump)
```bash
git commit -m "test: add unit tests for IP address assignment logic"
git commit -m "test(feature): add integration tests for device management"
```

### CI/CD Changes (No Version Bump)
```bash
git commit -m "ci: add semantic-release configuration for GitLab"
git commit -m "ci: optimize Docker build caching strategy"
```

### Maintenance (No Version Bump)
```bash
git commit -m "chore: update dependencies to latest versions"
git commit -m "chore(docker): update base image to PHP 8.2"
```

### Build Changes (No Version Bump)
```bash
git commit -m "build: update Vite configuration for production builds"
git commit -m "build(npm): add development dependencies for linting"
```

## Breaking Changes (Major Version Bump)

Für Breaking Changes füge `BREAKING CHANGE:` im Body oder Footer hinzu:

```bash
git commit -m "feat!: redesign user authentication system

BREAKING CHANGE: User model now requires email verification before login.
Migration required for existing users."
```

Oder alternativ:

```bash
git commit -m "refactor(api): change REST API response format

BREAKING CHANGE: API responses now use camelCase instead of snake_case.
Update all API clients accordingly."
```

## Multi-line Commits

```bash
git commit -m "feat(devices): add support for device groups and tagging

- Implement device grouping functionality
- Add tagging system for better device organization
- Update Filament UI to support group management
- Add database migrations for new group tables

Closes #123, #124"
```

## Scope Examples

- `auth` - Authentication und Authorization
- `devices` - Device Management
- `ip` - IP Address Management  
- `ui` - User Interface / Frontend
- `api` - REST API Endpoints
- `docker` - Docker/Containerization
- `db` - Database/Migrations
- `tests` - Test-related changes
- `docs` - Documentation

## Workflow für Releases

1. **Development**: Normale Commits in Feature Branches
2. **Merge**: Pull Requests in `main` Branch
3. **Release**: Merge `main` in `release` Branch für automatische Versionierung

```bash
# Feature entwickeln
git checkout -b feature/mass-ip-creation
git commit -m "feat(ip): add bulk IP creation via CIDR input"

# Pull Request erstellen und in main mergen
git checkout main
git merge feature/mass-ip-creation

# Release auslösen (nur bei wichtigen Updates)
git checkout release
git merge main
git push origin release  # Triggert semantic-release
```
